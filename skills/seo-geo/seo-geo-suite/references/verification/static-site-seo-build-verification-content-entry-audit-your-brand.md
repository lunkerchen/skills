# your-brand: portfolio entry audit recipe (verified 2026-08-11)

Repo: `$HOME/Developer/Projects/your-brand` — Astro 6, CF Pages,
pnpm, site `https://your-brand.your-app.example.com`.

## Baseline verify-seo numbers
37 pages / 101 JSON-LD blocks / 36 sitemap URLs / 31 llms entries.
Each new portfolio entry shifts: +1 page, +1 CreativeWork JSON-LD block,
+1 sitemap URL, +1 llms entry.

## Portfolio entry anatomy
- Content: `src/content/portfolio/<slug>.md` — frontmatter: `title`, `slug`,
  `date`, `category`, `tags[]`, `cover: "../../assets/images/<dir>/cover.webp"`,
  `featured` (schema in `src/content.config.ts`, cover optional + image()).
- Route: `src/pages/projects/[...slug].astro` — one static page per entry via
  `getStaticPaths()`. Emits CreativeWork JSON-LD: `name`=title,
  `image`=cover src absolute, `dateCreated`/`dateModified`=date ISO,
  `url`=Astro.url.href, `keywords`=tags.join(', '), `inLanguage`=zh-TW,
  author Person @id `https://your-brand.your-app.example.com/#person`,
  plus BreadcrumbList and a site-level WebSite/Person/Photographer graph.
- Images: `src/assets/images/<slug>/cover.webp` + `img1..N.webp` (VP8, ~4K).
  Build emits TWO hashed variants per image: `cover.<hash>.webp` (og:image /
  JSON-LD) and `cover.<hash>_<variant>.webp` (body `<img>`); both must exist
  in `dist/_astro/`.
- Sitemap: generated by `@astrojs/sitemap` → `dist/sitemap-index.xml` +
  `dist/sitemap-0.xml`; trailing slashes; `/contact` filtered in astro.config.
- llms.txt: source `public/llms.txt` hand-edited per entry — a single tracked
  diff line: `- <標題>: https://your-brand.your-app.example.com/projects/<slug> — <desc>`.
- dist/ is gitignored (`.gitignore:2`) — builds never pollute git status.


## Pitfalls hit on 2026-08-11
- `read_file` round-trip mangles JSON-LD extraction (line-number prefixes →
  false "Expecting ',' delimiter" on valid JSON). Extract via `node -e`
  `fs.readFileSync` from disk instead.
- execute_code python: `open(p, 'utf8')` raises `ValueError: invalid mode` —
  use `open(p, encoding='utf8')`.
- Regex-heavy extraction in inline shell (`for f in cover img1 …; grep -o
  "/_astro/$f\.[^\"']*\.webp"`) tripped the hardline command blocklist — do
  image-ref resolution in python/execute_code or a saved script.
- verify-seo.mjs does NOT assert per-entry CreativeWork name/date/image —
  acceptance audit must extract the CreativeWork block and assert those by hand.
